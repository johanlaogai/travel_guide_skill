# Intake：先问清楚，再排

## 必填

- 目的地（城市/区域；多城要问顺序）
- 日期，或“几天 + 大概月份”

日期明确时用 `dates` 算，不心算：

```bash
node bin/travel-guide.mjs dates --start 2026-11-28 --days 3 --holidays CN
```

## 默认值（用户没说时）

| 项 | 默认 |
|---|---|
| 人数 | 1 |
| 节奏 | 平衡（每天 2–3 锚点） |
| 预算 | 中档 |
| 交通 | 公共交通优先 |
| 住宿 | 市中心/地铁换乘方便 |
| 饮食 | 不特别限制 |
| 兴趣 | 经典 + 一点在地体验 |

把这些默认写进 `trip.meta`，并在交付时用一句话说明；不要假装用户确认过。

## 尽量补齐

- 出发地、到达/离开时间、车站/机场；
- 人数与关系（情侣/亲子/带老人/朋友）；
- 预算档与“哪些能省/哪些不能省”；
- 兴趣与“必须去/不想去”；
- 饮食、过敏、无障碍、带娃、老人步行上限；
- 是否自驾、能否爬山/走长路；
- 住宿区域/是否已订；
- 签证/证件/保险；
- 是否愿意为预约/免排队付费。

一次只问 1–3 个最关键的，不要盘问。能从上下文推断的先推断，再让用户纠正。

## 歧义处理

- 目的地同名：给 2–3 个候选（省份/机场/景点），让用户选。
- 日期歧义：明确“2026-11-28 是周六”；跨年/节假日要确认。
- “玩几天”与“几天几晚”不同：按住宿晚数确认。
- 多城：先确认顺序与交通，再排每天。

## 输出契约

在开始排程前，用 3–5 行复述：

```
目的地：广州
日期：2026-11-28 至 11-30（3 天 2 晚，周六至周一）
人数：2，平衡节奏，中档预算
必去：陈家祠、广州塔；不想：长时间排队
待确认：是否登塔、是否住北京路
```

用户确认后再进入 research/planning。若用户说“直接排”，按默认值排，并在交付时列出假设。

## 不开始的情况

- 目的地/日期完全缺失；
- 用户要求下单/支付/实时导航/签证法律意见；
- 用户要求绕过登录/批量抓取攻略；
- 用户要求把未经核验的内容写成“官方”。

明确说明做不到，给替代方案（官方链接、人工核验、用户粘贴内容）。
