# Revise：改行程的检查清单

改 `trip.json` 后，不要只改时间；重算受影响的一切。

## 改动类型

| 改动 | 必须重算 |
|---|---|
| 加/删锚点 | 当天 `transit`、饭点、闭馆、预算、地图 |
| 换天 | 日期/星期、天气、预约余量、住宿 |
| 改时间 | 前后 `transit`、饭点、末班、到达/离开 |
| 改人数 | 预算、住宿房型、预约人数、分账 |
| 改预算 | 分类区间、总预算、交通/住宿选择 |
| 带老人/小孩 | 锚点数、步行距离、电梯/无障碍、午休 |
| 换酒店 | 到达/离开交通、每天首末项 |
| 换城市 | 重跑 enrich、天气时区、交通、签证 |

## 步骤

1. 改 `days/items`；
2. 对每个非首项补/改 `transit`；
3. 检查时间重叠（`ITEM_OVERLAP`）和交通过紧（`TRANSIT_TIGHT`）；
4. 确认锚点 ≤3、有饭点、有天气来源；
5. 更新 `sources[]`/`sourceIds`；
6. 跑 `check --strict`；
7. `build` 后浏览器验收。

```bash
node bin/travel-guide.mjs check --trip <trip.json> --strict
node bin/travel-guide.mjs build --trip <trip.json> --out <dir>
```

## 常见错误

- 删了一个点，没改下一项的 `transit`；
- 换了日期，没重拉天气；
- 加了博物馆，没查周一闭馆/预约；
- 改了人数，预算和预约人数没变；
- 把“待核实”来源删了，却保留了“官方营业时间”文案；
- 公开版忘了 `--public`，泄露电话/订单号。

## 用户要求“只改一个点”时

也要检查它是否影响：

- 当天路线顺序/折返；
- 饭点；
- 闭馆/预约；
- 预算；
- 返程时间。

如果影响大，先说明取舍，再改。
