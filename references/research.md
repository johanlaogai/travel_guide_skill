# Research：官方核验清单

> 模型记忆不是来源。所有会变化的动态事实，都要落到 `sources[]`。

## 先跑 enrich

```bash
node bin/travel-guide.mjs enrich --trip <trip.json>
```

它会尝试：

1. Open-Meteo 地理编码（失败回退 Nominatim）；
2. 16 天内天气预报，超出用 archive 气候；
3. Overpass 周边 POI（候选）；
4. Wikimedia 背景/坐标/图片；
5. 非 CNY 时 Frankfurter 汇率；
6. Nager 公共假期。

`enrich` 只解决“底图/背景/候选”，不替代官方核验。

## 每个锚点必须核验

| 字段 | 来源 | 记录 |
|---|---|---|
| 开放时间/最后入场 | 官网/官方公众号 | `official` + URL + 访问时间 |
| 闭馆日/临时闭馆 | 官网/官方公告 | `official` |
| 票价/免费日/优惠 | 官网/官方票务 | `official` |
| 预约入口/放票时间 | 官方预约页 | `official` + URL |
| 地址/坐标 | 官方/Nominatim | `verified`/`community` |
| 交通 | 官方地铁/公交/铁路 | `official`/`verified`；时长可 `estimate` |
| 背景 | Wikipedia/Wikivoyage | `community` |
| 排队/体验 | UGC | `community`，不作为事实 |

## 搜索与抓取

- 优先站内搜索/官网导航，不用二手转载当官方。
- 每个事实只抓一页；不要批量抓整站。
- 记录 `title/url/retrievedAt/license/confidence`；页面打不开就 `unverified`。
- 官方页面只有英文/需要登录：记录你能看到的，标“待核实”，不要猜中文规则。
- 不用模型补全营业时间；不用“一般来说”当事实。

## 天气

- 16 天内：Open-Meteo forecast，`forecast`，写 `updatedAt`；
- 16 天外：archive/climate，`estimate`，写“气候估算”；
- 台风/暴雨/高温预警：官方气象台，`official`；给出替代日/室内备选。

## 交通

- 到达/离开：车站/机场 → 酒店的最后一程，写清方式、时长、末班；
- 城市内：地铁优先；打车写“可能堵车”；
- 跨城：高铁/航班班次以 12306/航司为准，不编具体车次；
- 交通时长是 `estimate`，不是官方承诺。

## 住宿

- 只给区域建议（交通/安全/夜间便利），不编具体房价/库存；
- 用户已订：记录区域/入住时间，不要在公开版写房间号；
- 带老人/小孩：减少换乘，优先电梯/无障碍。

## 餐饮

- 给区域 + 2–3 个候选，不把 UGC“必吃”当事实；
- 营业时间/排队/预约以官方/地图为准；查不到就写“以现场为准”；
- 饮食限制/过敏要显式记录。

## 签证/入境/保险

- 只给官方链接和清单，不给法律意见；
- 护照有效期、签证类型、入境卡、保险要求让用户自行核对；
- 海外紧急电话/使领馆信息放 `emergency`。

## 失败时

- API 超时：`--offline` 用缓存；无缓存就标 `unverified`，告诉用户哪几项没查到；
- 官方页面打不开：保留链接 + `unverified`，不要用记忆补；
- 信息冲突：列两个来源，标“待核实”，不要选一个看起来合理的；
- 无法核验的动态事实：从正式行程里删掉，或降级为“可选/到现场看”。
